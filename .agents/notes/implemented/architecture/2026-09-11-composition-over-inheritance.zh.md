# Agent Note：远程 worktree 用组合而非继承

Status: implemented

[English](2026-09-11-composition-over-inheritance.md) | 中文

## 问题

Harness 给一个会话恰好一个文件系统、一个子进程运行时、一个 shell。要让会话的工具跑在另一台机器上，就得替换这三个接缝，而最直接的做法是继承已发布的实现、只覆写需要跨网络的方法。

那条路会对已发布基类的每一次改动都收租：上游重命名一个 `protected` 字段、构造函数多一个必填参数、或者基类新增了一个子类没跟着覆写的方法，都会变成这个插件的问题；而插件为基类中它根本用不到的部分一直付费。这些接缝本身还是 `Service` 的子类，其 `protected` 成员让类型变成名义类型（nominal），于是即使某个位置本该接受一个普通对象，继承实现也换不进去。

隔离还有第二个问题：什么算一个"远程世界"，它的身份是什么？把仓库拷到机器上，身份就变成另一台主机上的一个路径，而且用户的检出不受影响；而每个任务切一个 `git worktree`，则让每个任务有自己的分支，合并回去是一次普通的本地 git 操作，而不是文件传输。

## 决策

**接缝一律组合，绝不继承。** 三个接缝都用 `ctx.provide` 注册——也就是 Cordis 自己的 `Service` 构造函数内部调用的那个原语——每个值都是一个普通对象，委托给在隔离作用域（`ctx.isolate(name)` + `ctx.plugin(Factory)`）里组合出来的已发布实现。本包不继承任何 Harness 类。不属于任何锚点的路径判定为本地并原样委托，因此没有配置机器的部署，行为与出厂组合完全一致。

**远程世界 = 锚点 + worktree。** 机器持有仓库，仓库持有 worktree。切出一个会在机器的 `.dsh-worktrees/worktree/<name>` 下创建真实目录、分支为 `worktree/<name>`，同时在本地创建一个只放元数据文件的锚点目录。锚点是所有工具看到的身份；机器路径才是 daemon 实际服务的对象。

**daemon 不依赖任何东西。** 它是一个纯 Node 程序，既不 import Cordis 也不 import 任何 `@deepseek-ai/*` 包，因此不会随 Harness 漂移，并且每次构建都打成单文件。

**转发由宿主建立。** 机器的 daemon 只绑定自己的 loopback。宿主挑一个空闲本地端口，经由操作者自己的 `ssh` 转发过去，于是 `~/.ssh/config`、`ssh-agent`、`ProxyJump`、堡垒机都按原有方式工作，而本地端口从不属于机器身份的一部分。

## 后果

- 已发布接缝实现的内部改动不会再波及本插件，除非接缝的公开契约变了——那时两边都在接缝处修。
- 路由器必须重新声明它所委托的 sandbox 模式，因为基类拒绝组合一个自称不设限的挂载。上报 `undefined` 曾让插件在真实 profile 里完全无法组合；该回归已有测试钉住。
- 两个持久化存储各自拥有提交点：节点与仓库文档先写盘、再替换内存列表，因此一次抛错的保存不会留下"调用方已被告知失败"却仍存在的记录。
- 浏览器半边以一个动态 CommonJS bundle 交付，没有样式通道，因此它的 CSS Module 在构建时被编译进产物、在求值时挂一个带标记的 `<style>`，而不是作为文件发出。
- `direct` 作为一种存储态保留，只为让 SSH 传输之前写下的文档仍能加载；没有任何入口会创建它。
